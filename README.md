
# areal-hr_ext — Учёт сотрудников

Учебный проект системы кадрового учёта сотрудников.

## Инструментарий

- **ОС:** Windows 11 + WSL2 (Ubuntu)
- **IDE:** Visual Studio Code
- **Бэкенд:** Node.js / NestJS / TypeORM
- **БД:** PostgreSQL 18
- **Контейнеризация:** Docker Desktop
- **Миграции:** node-pg-migrate

## Структура проекта

- `/api` — бэкенд на NestJS
- `/app` — фронтенд на Vue.js / Quasar (планируется)
- `/containers` — Dockerfile для бэкенда и фронтенда
- `/docs` — документация и схема БД
- `/api/migrations` — миграции PostgreSQL

## Требования для запуска

Перед запуском необходимо установить:

- Node.js и npm
- Docker Desktop
- Git

Docker Desktop должен быть запущен.

## Установка проекта

Клонировать репозиторий:

```bash
git clone https://github.com/Anton-Dev76/areal-hr_ext-test.git
cd areal-hr_ext-test
```

Установить зависимости бэкенда:

```bash
cd api
npm install
```

## Запуск PostgreSQL

Из корневой папки проекта выполнить:

```bash
docker compose up -d
```

Docker создаст контейнер PostgreSQL.

Параметры подключения:

| Параметр | Значение |
|---|---|
| Host | localhost |
| Port | 5432 |
| Database | hr_db |
| User | hr_user |
| Password | hr_password |

Указанные значения предназначены для локальной разработки.

## Настройка окружения

В папке `api` создать файл `.env`:

```env
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DB=hr_db
POSTGRES_USER=hr_user
POSTGRES_PASSWORD=hr_password

DATABASE_URL=postgres://hr_user:hr_password@localhost:5432/hr_db
```

Файл `.env` содержит параметры подключения к базе данных.

## Миграции базы данных

Для управления схемой PostgreSQL используется `node-pg-migrate`.

Миграции расположены в папке:

```text
api/migrations/
```

Каждая таблица создаётся отдельной миграцией.

Миграции используют формат CommonJS (`.cjs`) и содержат функции `up` и `down`.

### Применение миграций

Находясь в папке `api`, выполнить:

```bash
npm run migrate:up
```

Команда применяет все ещё не выполненные миграции.

При повторном запуске выполненные миграции пропускаются.

Информация о применённых миграциях хранится в таблице `pgmigrations`.

### Откат миграций

Для отката последней применённой миграции:

```bash
npm run migrate:down
```

Команда откатывает одну последнюю миграцию.

**Внимание:** откат миграций может удалять таблицы и данные. Использовать только при понимании последствий.

### Важно для существующих баз данных

Миграции рассчитаны на первоначальное развёртывание схемы в пустой базе данных.

Если таблицы были созданы вручную до внедрения `node-pg-migrate`, команда `migrate:up` может завершиться ошибкой из-за уже существующих таблиц.

Не следует удалять существующую базу с данными ради повторного применения миграций.

## Запуск бэкенда

После запуска PostgreSQL и применения миграций:

```bash
cd api
npm run start:dev
```

Если терминал уже находится в папке `api`, повторно выполнять `cd api` не нужно.

По умолчанию API доступен по адресу:

```text
http://localhost:3000
```

Для проверки сборки:

```bash
npm run build
```

## Решения по проектированию БД

### Паспорт и адрес (1:1)

Таблицы `passports` и `addresses` связаны с `employees` через ограничение `UNIQUE` на поле `employee_id`.

У каждого сотрудника хранится только актуальный паспорт и адрес без истории изменений.

Это решение принято намеренно, поскольку история паспортов в рамках данной системы не требуется.

### Soft delete

Для сущностей, поддерживающих мягкое удаление, используется поле `deleted_at`.

Вместо физического удаления запись помечается как удалённая.

Уникальность названий организаций проверяется среди активных записей через частичный уникальный индекс:

```sql
WHERE deleted_at IS NULL
```

### Ограничения удаления

Нельзя удалить организацию, если в ней существуют активные отделы.

Нельзя удалить отдел, если у него существуют активные дочерние отделы.

В этих случаях API возвращает HTTP 409 Conflict.
